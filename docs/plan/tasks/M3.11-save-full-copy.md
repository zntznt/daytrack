## Goal
Settings › Data › "Save a full copy (JSON)":
1. It writes `daytrack-YYYY-MM-DD.json` to `tmp/Exports/` first, using `CopyFileCodec`. The temp file is deleted as soon as the exporter closes (success or cancel), and `AppEnvironment` purges `tmp/Exports/` on every launch, so no copy lingers inside the app (Erase says Daytrack keeps no other copy).
2. It presents `.fileExporter`.
3. Only on success does it call `SettingsService.recordFullCopySaved`. Cancel is a no-op and says so.

The fact line reads "Last full copy: 12 Jul (11 days ago)" or "No copy saved yet". It is never a nag.

DEBUG `-uiTestExportTo <dir>` replaces the exporter with a direct write, so UI tests never touch the system sheet.

## Why it matters
During the MVP this is the only copy that exists. The store is excluded from backup (Q8).
