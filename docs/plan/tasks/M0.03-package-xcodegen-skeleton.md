## Goal
Create a `DaytrackKit` package (targets `DaytrackCore` and `DaytrackStorage`, plus their test targets) and a `project.yml`. XcodeGen turns `project.yml` into an iOS app, hosted unit tests and UI tests, all linked to the package, and all green on the iPhone 18 Pro simulator.

## Why it matters
Domain work (M1) needs `swift test` on the Mac host. Every UI task needs an app target that is reproducible from the CLI, with no pbxproj in git.

## Do
- `Package.swift`: swift-tools-version 6.2; platforms `.iOS(.v26)` and `.macOS(.v15)`; Swift 6 language mode.
- `project.yml`:
  - targets `Daytrack` (application), `DaytrackAppTests` (bundle.unit-test, hosted) and `DaytrackUITests` (bundle.ui-testing);
  - the local package `DaytrackKit`;
  - deployment target iOS 26.0 **[O7]**. Stop if gate G2 reports an older iOS;
  - bundle id `$(BUNDLE_PREFIX).daytrack` **[O10]**;
  - `configFiles` includes `Local.xcconfig` when it is present, and `Local.xcconfig.example` lists DEVELOPMENT_TEAM and BUNDLE_PREFIX;
  - a shared scheme `Daytrack` that runs both test targets.
- Info.plist is generated, never checked in: set `GENERATE_INFOPLIST_FILE: YES` and `INFOPLIST_KEY_UILaunchScreen_Generation: YES`. Without a launch-screen key iOS runs the app letterboxed.
- `App/DaytrackApp.swift` shows `Text("Daytrack")`.
- `scripts/verify.sh`: remove the "no project yet" short-circuit from M0.02.
- Record the output of `sw_vers -productVersion` and `xcodegen --version` from the Mac in the PR body.

## Out of scope
- Any domain type, screen, widget target, App Group or device signing.
- Checking in `Daytrack.xcodeproj`.
