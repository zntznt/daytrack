## Goal
- `AppEnvironment` is the only place adapters are wired. It builds `FileRecordStore` and `FileDeviceStateStore` on `Application Support/Daytrack/`, a `SystemClock`, and no-op `ReminderScheduling` and `WidgetPublishing`, which are replaced in M3.13 and M8.03.
- `RootView` routes to one of three places:
  - `.onboarding` when there are no trackers;
  - `.tabs` (a TabView with **Today** and **Settings** placeholders) when there are;
  - `.unreadable(keptAt:)` when the store reports it. This is a read-only screen that says the file was kept and where, with one "Continue" action that goes to onboarding (the file was already moved aside, so the store is now empty).
  - The route is re-evaluated whenever the record changes (one `@Observable` app state), so onboarding, erase and restore can switch it without touching RootView again.
- `LaunchOverrides`: the whole file is inside `#if DEBUG`. It parses `-uiTestNow`, `-uiTestTZ`, `-uiTestStore memory|<name>`, `-uiTestSeed <fixture>`, `-uiTestLockHour <0-23>` (applied to the seeded Settings) and `-uiTestScreen <name>` (README §6). The clock is an OffsetClock: it starts at `-uiTestNow` and then runs at real speed.
- Fixtures, all deterministic: `threeTrackersEmpty`, `eightTrackers`, `fortyDays`, `ninetyDaysWithRevision`, `yesterdayWhollyBlank` (also sets `reminderAt` 21:30 and DeviceState `remindersScheduledThrough` = today + 13, for M8.02) and `allArchived`.

## Why it matters
Every screen hangs off this root. Every UI test from here on needs a fixed clock and a fixed record.
