# M7.03 Restore picker and refusal screens

## Goal
- Settings › Data › "Restore from a copy" opens `.fileImporter`, limited to `[.json, .commaSeparatedText]` (what Daytrack writes, HANDOFF §8) and a single file. A CSV is read and refused with its reason **[O2]**, so the refusal is reachable (design-review Medium 19). Security-scoped access is held only while the file is read.
- Refusal screens cover "not a Daytrack file", "newer version" and "CSV cannot be restored". Each one names the file, says it read fine, and says that nothing on the phone changed. The heading takes focus through `AccessibilityNotification.ScreenChanged`. Refusals are never alerts.
- Cancel is a no-op and says so.
- DEBUG `-uiTestRestoreFile <fixture>` skips the system sheet. The fixtures are `UITests/Fixtures/*.json`, which are copied into the app bundle in DEBUG builds.

## Why it matters
design-review Medium 19 found that the refusal screens could not be reached. HANDOFF §8 sets the picker rules.
