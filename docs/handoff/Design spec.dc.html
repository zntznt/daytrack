Daytrack · design specification

One constraint, and everything that follows from it.

Daytrack is opened once a day, usually in bed, usually in the dark. Every decision below is downstream of that. Where a value is stated it was measured from the running app, not estimated.

The rule, and its one declared exception
Surfaces and the default accent stay near blue-free, measured at 0–11% blue channel. Text is allowed ~40% because legibility beats dogma. Three optional accents deliberately exceed the ceiling: each carries its measured figure on the swatch and warns when chosen, which is the only sanctioned way past this rule. Any new colour is measured before it ships, never eyeballed.
01 · Colour

Nine tokens in one hue family, and a declared way out

Every token sits between hue 60 and 100 in oklch, and there is no grey, because a neutral grey reads blue against this palette. Lightness carries all hierarchy. The optional accents below are the one place the app leaves that band, by choice and with the cost stated.

02 · Type

Two families with strict jobs

The split is numerals against words, not language against data. IBM Plex Mono carries numbers, dates, counts and uppercase labels, where tabular figures keep columns from dancing as values change. Instrument Sans carries language, and also carries word-scale values: Moderate is a measurement, but it is still a word, and setting it in mono makes it look like a code. Two of the three tracker types are worded, so this is the common case rather than an exception, and the size drops with it, from 25px mono down to 14.5px sans, because a word needs no room to be read.

{{ t.role }} {{ t.sample }} {{ t.spec }}
Five display steps, and the sub-screen step covers 23 to 25px: week and month titles sit at 23, the day detail at 24, confirmations at 25. Treat those as one step and pick by how much sits beside the heading. Tracking splits on brand against interface, not on size. The wordmark and the onboarding hero take −.035em because brand type is set tighter; every interface display size takes −.03em, whatever its size. That is why the 21px wordmark is tracked tighter than the 30px board day, and within Instrument Sans it is the one place where a smaller size is set tighter than a larger one. Below the display sizes there are two more negative steps, both easy to miss and both load-bearing: numerals take −.02em, including mono numerals, because Plex Mono at 25px opens up more than the row can afford; interface labels and word values take −.01em. Mono is therefore tracked in both directions, negative when it is a number and positive when it is an uppercase label, where +.09 to +.14em is what makes 10px caps readable at all. Body text takes none.
03 · Space and shape

Radius signals scale, not decoration

RADIUS
{{ r.v }} {{ r.use }}
RHYTHM
The icon tile's radius runs at roughly 28% of its own size, 15 on 52 and 18 on 64, which are 28.8% and 28.1% rather than one constant. The favicon and the SVG mark are cut to the 52px ratio. If a third tile size is ever needed, take 28.8% and round to a whole pixel. Related items cluster at gap 8 / 11 / 12. Sections are separated by margin-top, and that is the one place a margin is the right tool. The section label ships at 22, 26, 28 and 30px, with 28 accounting for 8 of the 19 uses; the onboarding and printed-sheet labels, which are styled differently, sit at 34. Treat 28 as the step and only leave it when a screen is unusually dense or unusually empty. Everything inside a section is spaced with a flex gap, which survives reordering and deletion where source whitespace and per-item margins do not.
Phone screens pad 26px top and 22px at the sides; printed sheets pad 52px top and 54px at the sides, which is roughly double and is what keeps a sheet from reading like a screenshot. Minimum hit target is 44px. Where a control looks smaller than that, it is padded out with negative margins so the visual size stays honest.

Marking what is PWA and what is native

Both packagings ship, so the prototype badges every frame that exists in only one of them. Most of the app is unbadged: the board, the record, the statistics and the printed sheets are identical either way. The badge sits above the phone, never inside the screen — it is a note to the reader, not UI.

PWA Home-screen build only — install, icon badge and long-press, the update strip and “What changed”, the caching states, and the two home-screen scheduling panels.
NATIVE Native build only — the permission prompt, notification actions, the real widget, the two native scheduling panels, and the storage screen where backup is excluded.
Badge Plex Mono 400 · 9px · +.1em, radius 4, padding 4/6. PWA takes --ln border and --ft text; NATIVE takes --ok for both. The accent is not used — a badge is not a state of the app.

Curve is cubic-bezier(.22,1,.36,1) throughout, except the 120ms handle scale which takes the browser default — it is a pressure cue, not a position, and easing it makes the finger feel late.

The eight-tap interaction, frame by frame

Eight tracks, one press each, ten seconds. The governing rule: no motion may sit between a press and the value being visible. On every entry path except the keyboard, the new value paints on the first frame after the event — the eased curve above never actually plays during a drag.

01pointerdown0ms
The value is set from the press x immediately — not on first move. The pointer is captured, transitions on fill and handle are dropped in the same state change, and the handle jumps to 1.18. Because the transition string is removed on the frame the drag begins, the jump to the finger is instant rather than a 160ms slide from wherever the value used to be. The numeral recolours --tx → --ac, uncoloured and unanimated, as a "you are holding this" signal.
02pointermoveper event
The value is recomputed per pointer event and quantised to the stop grid — eleven stops for a 0–10 track, one per label otherwise. There is no interpolation and no smoothing: the fill width is the value. The handle therefore snaps between stops rather than gliding, which is correct — the data is discrete and the control should not imply otherwise.
03pointerup120ms
Transitions are restored on the same frame, but nothing moves — the value is already where the finger left it. The only motion that ever plays at the end of a drag is the handle relaxing 1.18 → 1 over 120ms. No commit flourish, no checkmark, no row collapse. The value standing still is the confirmation.
Tap path
The stepper pad opens with no transition, commits on tap, and closes on the same frame. Two taps, zero animation. The setting exists for people who find aiming hard — a pad that animates open is a pad you have to wait for.
Keyboard path
Arrows step ±1, Home and End jump to the ends. This is the only path where the 160ms fill is visible on the board — the one case where the value changes without a finger already sitting at the destination.

Haptics

PWA NATIVE

One event only: a selection tick each time the drag crosses a stop — UISelectionFeedbackGenerator on iOS, CLOCK_TICK on Android. Nothing on pointerup, nothing on the eighth track, nothing when the day closes. Eight tracks a night is roughly eighty ticks; a success buzz on top of that is punishment, and a celebration for recording a bad day is the exact tonal failure §06 exists to prevent. PWA: the Vibration API is unavailable on iOS Safari and coarse elsewhere — ship the tick native-only and degrade silently. No fallback, no setting, no explanation on screen.

Two rules for anyone extending this

The board never re-renders under a moving finger. If the day-close boundary is reached mid-drag, the lock is deferred and fires on pointerup instead. Any future timed change to Today must defer the same way.

Reduced Motion changes nothing about the primary interaction — the drag path has no motion to remove. Only the chevron and the keyboard fill stop easing. If a new effect would make the app feel different with Reduced Motion on, it does not belong here.

06 · Voice

State the fact, then say why it is fine

Daytrack asks people to record how bad things are. It cannot also be cheerful about it. The voice is plain, specific, and never congratulates. There are no streaks to break and nothing to be proud of, only days that were written and days that were not.

07 · Paper

The report inverts everything

Printed sheets are ink on warm white at Letter 612 × 792, one section per sheet, amber demoted to a spot accent. The dark palette exists for a phone at night; paper has the opposite problem. Vocabulary shifts too. The screen says you, the sheet says the patient, and clinical terms of art that would sound evasive in the app are correct there.
